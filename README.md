# GINA 牌友会

采用v2暖色会所美术的本地掼蛋游戏，纯HTML/CSS/JavaScript，无构建与外部依赖。支持本机练习和同Wi-Fi局域网对战，后续将开发斗地主与麻将。

![GINA Card Game](assets/guandan-club-v2.png)

## ✅ 当前进度 · 2026-09-23

**1.3.0 · WebRTC P2P 直连与 v2 会所视效全面融合（公网即开即玩）**
- 🚀 **零成本 WebRTC P2P 架构**：引入 PeerJS 直连，房主浏览器直接作为权威裁判节点，其他三位玩家低至数十毫秒瞬时直连；无需自建后端服务器，彻底摆脱 Netlify 函数额度限制与 Blobs 延迟，可直接挂载于任意静态托管平台（GitHub Pages / Cloudflare Pages / Vercel / Netlify 等），永久免费。
- 🎨 **房间页全面融合 v2 暖色会所美术**：`room.html` 彻底告别简陋排版，完整复刻圆角暖色牌桌、环形四方座位、金色行动指示灯（Turn Chip）与出牌飞入动效。
- 🤖 **15 秒超时 / 掉线 AI 智能代打**：任何玩家切后台、网络断开或 15 秒无操作，主机自动唤起 `GD.bot` 进行合规代打，并在玩家归来时无缝切换回手动，杜绝一人卡住全桌卡死。
- 🔗 **一键分享邀请链接**：房主建房后一键复制含 `?room=XXXX` 的专属进房链接，好友点击自动直达对应牌桌。
- 👆 **移动端滑动连续选牌**：支持触控或鼠标拖拽滑动批量连选扑克牌，出顺子、钢板更丝滑。
- 🔊 **Web Audio 合成音效**：将清脆的出牌、不要与胜利音效同步引入多人对局。
- 🔄 **向后兼容本地服务模式**：依然兼容 `node server.cjs` 局域网离线对战。

**历史修复（1.2.0 · 线上房间竞态）**

Netlify Blobs 线上实测：写入 3~11 秒才可读、强一致性不可用、`list()` 列表滞后数十秒。
据此重写了线上房间层，核心是「一个键只有一个写者」，并补了三类竞态的回归测试：

- 🔧 **并发准备丢更新**：四人同时点准备时，共享记录的读-改-写互相覆盖，
  服务端最终只看到 2 人已准备 → 牌局永远开不了。改为每人只写自己那把钥匙。
- 🔧 **开局依赖 list()**：靠列举认领键判断「四席齐且都准备」，而列表滞后数十秒 → 开局不触发。
  现在完全不调用 `list()`：座位是四个固定的已知键，直读即可。
- 🔧 **并发加入抢座 / 被覆盖**：滞后视图让后来者以为空席可用，把先到者覆盖掉，
  被覆盖者的令牌再也解析不出座位（一直报会话失效）。现在被覆盖者会补回座位，
  并有「必须确有空席才补占」「补占后反向核对让出多余席位」「回收重复占位」三重保护。

**本轮修复（1.1.0 · 线上打不开）**
- 🔧 `app.js` 语法错误：一行 `//` 注释吞掉了后面的闭合括号，整个脚本解析失败，
  导致线上页面完全打不开。已修复，并把语法检查写进构建，防止复发。
- 🔧 `netlify.toml` 的 `/* → /index.html` 通配兜底会把 `/room.html`、`/assets/*.png`、
  `/engine.js` 全部返回 index.html，房间页与背景图因此失效。已移除该兜底，
  改为显式 `/api/* → Netlify Function`；构建会校验该配置。
- 🔧 线上函数把牌局 JSON 存进 Blobs 会丢掉 `g.random` 函数，`deal()` 依赖它洗牌，
  导致**第二副必定崩溃**。已在读取房间时重新挂回 `random`。
- 🔧 多人**还贡**无法完成：贡还阶段统一走 `GD.act()` 会抛「还没轮到你出牌」。
  服务端（函数与本地服务器）与房间页均已改为该阶段调用 `GD.giveBack()`。
- 🔧 本地 `server.cjs` 重写时漏掉 `GD=require('./engine.js')`，四席准备后发牌即报
  `GD is not defined`；并误把端口写死，已恢复 `PORT` 环境变量支持。
- 🔧 「房主开房占两个座位」：带旧令牌再次加入会新占一座。现改为先认原座位再分配新座。

## 🎮 快速开始

### 本机单人模式

1. **直接运行**：双击 `index.html`，或使用命令 `open index.html`
2. **游戏流程**：
   - 每次加载自动开一场，从2开始
   - 你在下方，对面的阿棠是队友
   - 点击手牌选中后出牌，也可点击提示
   - 百搭的多种牌型在下拉框中选择
   - 轮到还贡时选一张小牌确认
   - 每副结束点"下一副"；过A后可重新开场

### 线上四人房间（推荐，异地也能玩）

1. **打开线上地址**：`https://guandan-party-room.netlify.app/`（或你自己的 Netlify 域名）
2. **房主**：进入 `room.html`（首页右上角「四人联机房间 ↗」），填名字 → 点「创建房间」
3. **其他三人**：打开同一个地址，填名字 + 房主给的**房间号** → 点「加入房间」
4. **口令**：固定为 `gina`（界面已预填）
5. **开局**：四人各点一次「准备」，自动发牌；房主在每副结束后点「下一副」

房间状态存在 Netlify Blobs，**不需要任何一台电脑常开**，也不需要同一 Wi-Fi。
每个会话只能收到自己的手牌，出牌由服务端校验座位、轮次、持牌与牌型。

### 本地四人模式（同一 Wi-Fi，可选）

1. **启动服务**：`node server.cjs`（如需换端口：`PORT=8799 node server.cjs`）
2. **创建房间**：房主打开 `http://127.0.0.1:8769`
3. **加入房间**：其他人用同一 Wi-Fi 中房主电脑的 IP 加 `:8769` 打开页面
4. **开局**：四人均点击准备后自动发牌

注意：本地模式的口令 `gina` 只用于局域网轻量访问，**不是公网安全认证**；结束后按 `Ctrl-C` 关闭服务。

## 🔧 技术特性

### 核心技术栈
- **前端**：原生HTML/CSS/JavaScript，无框架依赖
- **后端**：Node.js HTTP服务器，无第三方依赖
- **规则引擎**：独立的game logic，可在浏览器和Node.js运行
- **网络通信**：HTTP短轮询，Bearer Token鉴权

### 游戏特性
- **108张完整掼蛋规则**：包括所有基础牌型和特殊规则
- **红桃级牌百搭**：支持多种百搭组合声明
- **升级赛制**：完整的升级、接风、贡还、抗贡、冲A流程
- **智能AI**：基础启发式算法，适合练习使用
- **响应式设计**：支持桌面和移动设备

## 🆘 常见问题

### Q: 游戏无法启动怎么办？
A: 检查浏览器是否支持现代JavaScript，或尝试使用Chrome/Firefox最新版本。

### Q: 多人游戏无法连接？
A: 确保所有设备在同一Wi-Fi下，检查防火墙设置，确认服务端正在运行。

### Q: 音效没有声音？
A: 音效默认关闭，点击游戏界面中的"声音：关"按钮可开启。

### Q: 游戏规则有疑问？
A: 查看 `RULES.md` 文件了解详细规则说明。
